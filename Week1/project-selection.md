##2. Project 1: CI/CD Pipeline
### Problem Statement
Modern software projects undergo frequent changes. Manually testing, building, and deploying every change is repetitive, time-consuming, and susceptible to human error.
A Continuous Integration and Continuous Deployment (CI/CD) pipeline automates these processes and provides a repeatable software delivery workflow.
### Objective
The objective of this project is to design and implement a multi-stage CI/CD pipeline that automatically validates application changes and performs the required build and deployment processes.
### Planned Technologies
- Git
- GitHub
- GitHub Actions
- Docker
- Automated testing
- Linux
- Shell scripting
### Planned Pipeline
The intended workflow is:
Developer Change
Git Commit
GitHub Push
Automated Testing
Application Build
Docker Image Build
Deployment
### Expected Outcome
At the end of the project, I intend to have a reproducible CI/CD pipeline containing multiple stages for testing, building, and deployment, with appropriate deployment triggers.

## 3. Project 2: Infrastructure as Code
### Problem Statement
Manually creating and configuring infrastructure can produce inconsistent environments and makes infrastructure changes difficult to reproduce and track.
Infrastructure as Code provides a method of defining infrastructure using version-controlled configuration files.
### Objective
The objective of this projectis to define and provision infrastructure through code while applying concepts such as modular configuration, state management, variables, outputs, and secure handling of sensitive configuration.
### Planned Technologies
- Terraform
- Cloud infrastructure
- Git and GitHub
- Linux
- Environment variables
- Infrastructure configuration files
### Expected Outcome
At the end of the project, infrastructure required by the application will be defined as code and capable of being provisioned through a repeatable workflow.
